# 候选17：基于几何安全空间的渲染近裁面

本候选从已发布的candidate15重新建立，不包含candidate16的路缘底片裁切。已确认的商城斜视缺面被列为回归用例，原道路和底片几何全部保留。

## 方法与边界

只改变送入renderer的相机副本，不改变控制、交通模拟、拾取和缓存流送使用的源相机。屋顶、广场、道路、标线、桥面底部、车人及材料均保持candidate15。

每一帧在交通和LOD等更新后，求相机到所有可见网格世界轴对齐包围盒的最小距离。扣除0.25米保守余量，并利用实际投影矩阵计算视锥四角方向，使新的近裁面整个矩形都位于该无几何安全球内，再留10%余量；最大近裁面64米。这个约束也涵盖宽屏、竖屏和非对称投影。场景空间不足时保留原近裁面。

包围盒不是碰撞网格或道路高度假设。原网格均被保守包围，因此在当前场景的无顶点位移假设下，不会为提高深度精度而裁掉原本可见的实体。可见自动LOD会先按本帧源相机更新。几何版本、interleaved数据版本、实例矩阵版本和实例数量变化均使相应边界失效并重算。

蒙皮、活动morph、位移贴图、ShaderMaterial/RawShaderMaterial、线/点/精灵及特殊相机保守回退。项目现有着色器只改颜色、法线及辅助varying，未发现改变顶点位置。未来若添加onBeforeCompile顶点位移或渲染前修改实体，需要重审这些假设；当前唯一onBeforeRender封装仅记录绘制统计。

北京全城与CBD细览调用同一模块。全城入口在焦点位于CBD时启用，检查完整宿主scene，不能仅检查CBD而漏掉附近北京建筑。非CBD焦点保持原来行为。独立CBD的对数/反向深度实验保持原配置，不同时叠加此标准深度近裁面策略。

## 数值与行为验证

- 336组预设机位、三种宽高比及多级缩放均通过安全球/近裁面约束；84组允许提高near。商城1–2倍和多数近景保持原near，不能称全机位均有改善。
- 已知candidate16坏点：商城机位[4530,40,-385]到[4897.4207357,0.52999997,-344.6122843]的实际射线，candidate17保持同一ground 1,-1网格命中及坐标，不再产生此前的缺面。
- 900帧、30秒双进程回归包含商城与CBD街块之间反复移动、三种宽高比、两次画质切换。478帧提高near。30个检查点的完整车辆和行人记录，以及625个网格的顶点属性、索引、实例、矩阵及可见性与原模拟/LOD流程完全一致。
- 这900帧的Node CPU测量：near准备中位0.551ms，P95 0.919ms，最大19.560ms（含首次构建）。这是CPU测试，不能当浏览器FPS或GPU数据。
- 独立审查另跑600帧：预热P50 0.886ms、P95 2.199ms，冷启动约23ms。独立结果保留，不能合并当同一次测试。
- 动态几何/实例/数量、流送新增邻居、LOD换层、宽屏及非对称视锥、源相机隔离和诊断开关单元测试通过。

按24位标准透视深度解析估算，CBD街块缩放到约2264米时，near .35→64米对应约184.8倍深度精度；12厘米道路层差由约0.326个量化级变为60.24级。此为理想深度预算，不含实际GPU插值、遮挡或polygonOffset，不能等同动态画面证明。
